## **I. Introduction**

1. Object storage service to store files in **buckets** (globally unique names, region-scoped).
2. **Charged per GB-month + requests + transfer**.
3. Naming: lowercase only, 3–63 chars, not IP format.
4. **Objects = key + value (content)**
    - Key = prefix + object name (s3://my-bucket/folder/test.txt)
    - Max size = 5TB (single PUT limit = 5GB → use multipart upload above that).
5. Metadata (system/user), Tags (≤10), Versioning (null assigned to old objects if enabled later).
6. Pre-signed URLs let clients upload/download directly without stressing backend.

---
## **II. Encryption**

1. **SSE-S3** — AES-256, keys managed by S3.    
    - Header: "x-amz-server-side-encryption": "AES256".
2. **SSE-KMS** — Uses KMS CMKs, audit + rotation.
    - Header: "x-amz-server-side-encryption": "aws:kms".
3. **SSE-C** — Customer manages key, must supply per request.
4. **Client-side** — Encrypt/decrypt before/after upload.
5. **In transit** — Always use HTTPS.
6. Buckets can enforce **default encryption**.

---
## **III. Security**

1. **Access control**
    - IAM policies (preferred), bucket policies, ACLs (legacy).
    - Explicit deny overrides.
2. **Bucket policy use cases**
    - Public access, force encryption, cross-account access.
3. **Block public access** settings → recommended unless bucket must be public.
4. **VPC endpoints** for private access to S3.
5. **Audit**: CloudTrail for API calls, server access logs in separate bucket.
6. **MFA delete** for versioned buckets.
7. **Pre-signed URLs** for temporary access (download/upload).

## **V. Consistency**

- **Strong Read-After-Write consistency** (since Dec 2020) for all operations at no cost.
- No need to design around eventual consistency anymore.

---

## **VI. Advanced Features**

1. **MFA Delete** — prevent permanent deletion without MFA.    
2. **Object Lock** — WORM (Write Once Read Many compliance).
3. **Glacier Vault Lock** — regulatory retention.
4. **Event notifications** → SQS, SNS, Lambda (<60s delivery).
5. **S3 = key-value store** (key=path, value=object).

## **VII. Replication**

1. Must enable **versioning** in source + destination.
2. **Cross-Region Replication (CRR)** → compliance, latency, x-account.
3. **Same-Region Replication (SRR)** → aggregation, redundancy.
4. Only new objects replicated, deletes not replicated.
5. Replication Time Control → SLA <15 min for 99.99%.

---

## **VIII. Storage Classes**

1. **Standard** — 99.99% avail, 11 9s durability, multi-AZ.    
2. **Standard-IA** — Lower cost, 99.9% avail, multi-AZ.
3. **One Zone-IA** — Cheaper, single AZ, 99.5% avail.
4. **Intelligent Tiering** — Auto-moves between frequent/IA tiers.
5. **Glacier** — Archive, 90d min storage, 3 retrieval modes (1 min–12h).
6. **Glacier Deep Archive** — Cheapest, 180d min, 12–48h retrieval.
7. **Reduced Redundancy Storage (deprecated)**.

## **IX. Lifecycle Management**

1. **Transition actions** — move objects (→ IA, → Glacier).
2. **Expiration actions** — delete old versions, logs, incomplete uploads.
3. Can apply by prefix or tag.

---

## **X. Performance**

1. Scales automatically, ~100–200ms latency.    
2. At least 3,500 PUT/POST/DELETE and 5,500 GET/HEAD per prefix. Unlimited prefixes.
3. **Multipart upload** → recommended >100MB, required >5GB.
4. **Transfer Acceleration** → upload via edge location.
5. **Byte-range fetches** → parallel reads, resilience.
6. **KMS quota** can bottleneck if every request encrypted via KMS.

## **XI. Special Features**

1. **Requester Pays** — requester covers request + transfer fees.
2. **Object Lambda** — transform objects on the fly (e.g. redact PII, resize images).
3. **Access Points** — easier multi-tenant access control.
    - Each access point has its own policy.
    - **VPC-only access points** restrict S3 to VPC.
4. **S3 Storage Lens** — org-wide usage/activity analytics.

---

## **XII. Tips**

1. S3 Standard, IA, Glacier store across ≥3 AZs. One Zone-IA = 1 AZ.    
2. Access control: IAM > bucket policy > ACL (legacy).
3. Pre-signed URLs for temp access.
4. Lifecycle rules → save costs (Standard → IA → Glacier).
5. Never host static sites on EC2/Lightsail if S3 suffices.
6. S3 Select: run SQL queries directly on objects.
7. S3 Batch Ops: mass tag/ACL/metadata changes.
8. Use **Intelligent Tiering** if unsure.
9. For cross-account copy: bucket policy (source) + IAM policy (dest).
10. For static sites with custom domain: bucket must match domain name.
